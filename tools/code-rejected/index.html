Because the code is a one-time code: it is only good for a short window, then a fresh one replaces it. Your app and the service are both working from the same changing sequence, so they agree on which code is live right now — no code ever travels between them in advance.

That short life is the protection. A code someone steals — glimpsed over a shoulder, pulled from an old screenshot — quickly becomes useless, because by the time they try it, the window has closed. It is also the most common reason a correct-looking code gets rejected: you typed the right digits, just a few seconds too late.

Go back to the top and work through the four checks again, in order, slowly. The two that catch people most are the ones that look right at a glance: the code came from the row for a different account on the same service, or it rolled over while it was being typed. A fresh code, from the right row, typed promptly, settles most of what is left.

If it still fails, stop troubleshooting the code and use another way in — backup codes, a passkey, or the service’s recovery door on the last card of the diagnoser above. And one warning while you work: do not delete the account’s row in the authenticator app. Deleting the row can remove your only way in, and no support line can put it back.

Never read the code out. Hang up. No real company calls or texts to ask for your six-digit code — not your bank, not Google, not Microsoft, not anyone. That call is a break-in in progress: the caller already has your password and is stuck at the one door only you can open, and the code is the key.

If the call worried you — it claimed a charge, a lockout, a problem with your account — do not use any number or link the caller gave you. Open the service’s real app, or type in its real site address yourself, and check there. If everything looks normal, it was: the call was the whole attack.
